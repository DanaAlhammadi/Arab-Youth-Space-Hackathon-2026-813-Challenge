## Main reproducible notebook

The required main analysis notebook is:

```text
notebooks/02_main_analysis.ipynb
```

It is designed to run end-to-end using the committed sample inputs.

The notebook:

- loads the AOI-A and AOI-B ArcGIS-derived segment-statistics tables;
- performs data-quality checks;
- converts the AOI-A Landsat `ST_B10` sample using the project conversion;
- creates a thermal-context map for AOI-A;
- computes transparent relative thermal-screening scores from the supplied segment statistics;
- records thermal-pixel support;
- exports segment-level results and figures.

The notebook does **not** re-segment roads.

## Landsat handling

The project uses the following conversion for the Landsat Collection 2 Level-2 `ST_B10` sample:

```text
Kelvin = DN × 0.00341802 + 149.0
°C = Kelvin - 273.15
```

DN `0` is treated as fill/no-data.

This conversion is used only for the appropriate Landsat `ST_B10` product. It must not be applied to ECOSTRESS or another sensor with different product units.

---

## Segment screening method

For each AOI, the notebook uses:

- minimum temperature;
- median temperature;
- maximum temperature;
- temperature range;
- valid-pixel count.

The current transparent score is:

```text
priority_score = max(z_median, 0) + max(z_range, 0)
```

The score represents relative thermal screening priority **within the AOI**.

It is not a probability of damage and is not an engineering condition rating.

Support is reported separately:

```text
30+ valid pixels    HIGH SUPPORT
10-29 valid pixels  MEDIUM SUPPORT
<10 valid pixels    LOW SUPPORT
```

These are reporting thresholds, not a calibrated confidence model.

## Judge run instructions

### Colab

Open the notebook from GitHub in Colab.

The notebook detects Colab and clones the repository automatically.

Run:

**Runtime → Run all**

### Local

From the repository root:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
jupyter lab notebooks/02_main_analysis.ipynb
```

Restart the kernel and run all cells.

No GPU is required.

## Scientific claim boundary

THABAT is a screening and prioritisation tool.

It does not currently claim to:

- diagnose cracks or potholes;
- prove structural failure;
- prove pavement deterioration;
- establish rainfall causation;
- certify road safety;
- replace engineering inspection.

The current PoC produces an evidence-based starting point for physical inspection.
